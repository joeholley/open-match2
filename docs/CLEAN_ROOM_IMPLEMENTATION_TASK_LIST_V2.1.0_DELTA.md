# Open Match 2 and Open Match Ecosystem v2 — v2.1.0 Delta Clean-Room Implementation Task List, Engineering Specification, and Git Commit Plan

## Purpose and Scope of This Document

This document is the clean-room engineering specification and git commit plan for every change that is on disk but not yet committed, relative to the latest commit on the **v2.1.0-clean-room** branch of each repository. It continues **CLEAN_ROOM_IMPLEMENTATION_TASK_LIST_UPDATED.md** (same directory), which specified the changes from **main** to **v2.1.0-clean-room** in Commits 1–28 and Epics 1–20. Commit and epic numbering continue from there.

1. **Open Match 2 Core Repository (open-match2)**: baseline **v2.1.0-clean-room** at commit **ffef054**. 12 files modified, in Commits 29–31 (Epics 21–23). The changes make **InvokeMatchmakingFunctions** behave like an RPC framework from the caller's point of view:
   - every response an MMF streams back is returned to the caller;
   - invalid ticket IDs are listed on the returned match, and so are failed deactivation writes (only when om-core waits for deactivation);
   - MMF failures end the stream with an aggregated error status after all matches are sent.

   They also size MMF request chunks from the actual serialized protobuf so every chunk stays under the 4 MiB gRPC message soft limit, and update the documentation, protobuf comments and agent skill to match.
2. **Open Match Ecosystem Repository (open-match-ecosystem/v2)**: baseline **v2.1.0-clean-room** at commit **a6233f1** (the branch **v2.1.0-segmented-load-test** points at the same commit). 48 files (41 modified, 7 new), in Commits 32–43 (Epics 24–35). They cover:
   - the RESTful Open Match client: method-generic requests, error-returning **InvokeMatchmakingFunctions**, per-attempt timeouts, retry classification, token cache rework, and the new **DeactivateTickets**;
   - the matchmaking queue: Poisson ticket arrivals, confirmed-per-cycle metrics, request abandonment, ticket expiry tracking, and accurate HTTP status codes;
   - the game server director: two-pass proposal handling, MMF feedback responses, invocation error accounting, handling of invalid and failed-deactivation tickets, and safe shutdown;
   - the matchmaking functions: FIFO ordering, bounded unique names, a feedback-carrying debug MMF, 4 MiB message limits, and bounded graceful stop;
   - assignment distribution, protobuf extension helpers, logging and metrics initialization, and the mock game client;
   - the three example entrypoints: bounded shutdown, isolated HTTP servers, POST-only ticket intake, director-driven exit, and skill-tier segmentation;
   - the Cloud Build and GKE manifests, and the English and Japanese documentation.

## Epic 21: InvokeMatchmakingFunctions RPC Pass-Through Semantics, Ticket Annotations, and MMF Failure Reporting (Commit 29)

### Task 21.1: Forward Every MMF Response, Annotate Invalid and Failed-Deactivation Tickets, and Return Aggregated MMF Failures in main.go (Commit 29)
- [ ] **File**: **main.go** (Modified, package **main**; only the parts listed in this task. The request-chunking refactor in the same file belongs to **Commit 30**, Task 22.1, and must NOT be applied in this commit.)
- **Commit**: **Commit 29** (**feat(core): forward every MMF response and report invalid tickets, failed deactivations, and MMF failures**)
- **Justification**:
  1. **Silently Dropped MMF Responses**: At the baseline, **InvokeMatchmakingFunctions** discarded (with a Warn log "Skipping deactivation for match with no tickets.") every match whose rosters contained zero valid ticket IDs, which also covered matches with no rosters at all and responses whose **match** field was unset. MMFs legitimately send ticketless matches (diagnostic or feedback matches intended for the Director), so om-core was hiding MMF output from its caller. om-core must behave like an RPC framework: every response an MMF streams back reaches the caller.
  2. **Silently Hidden MMF Failures**: The MMF fan-out goroutine returned its error to nowhere (the goroutine's return value was ignored), and the handler always returned nil. A caller could not distinguish "the MMF made no matches" from "the MMF crashed, could not be dialed, rejected auth, or had an invalid URL". The handler must report every MMF failure to the caller, after all matches that were produced have been streamed.
  3. **Unreported Undeactivated Tickets**: om-core silently skipped invalid roster ticket IDs (it cannot deactivate them) and silently logged failed deactivation writes. A Director receiving the match had no way to know which tickets om-core did not deactivate on its behalf and may therefore still be active and matchable again.
  4. **Metric Ambiguity**: **om_core.match.received** previously counted only matches with valid tickets. Since every match is now returned, the counter must count all of them while still letting operators separate ticketless matches, via a new boolean attribute.
- **Implementation Details**:
  1. **Imports**: Add **google.golang.org/protobuf/protoadapt** (for the **protoadapt.MessageV1** element type of the status-details slice) and **google.golang.org/protobuf/types/known/structpb** (for **structpb.NewList** and **structpb.ListValue**). The following imports used by this task already exist at the baseline and must remain: **google.golang.org/genproto/googleapis/rpc/errdetails** (for **errdetails.ErrorInfo**), **google.golang.org/grpc/codes**, **google.golang.org/grpc/status**, **google.golang.org/protobuf/types/known/anypb**, **fmt**, **strings**, **sync**, and **github.com/pkg/errors** (whose **As** function is used for status unwrapping). No imports are removed.
  2. **New Exported Match.Extensions Key Constants** (declare immediately after the existing exported constant **MatchDeactivationTimeoutExtensionKey**, whose value **"deactivation_timeout"** and behaviour are unchanged):
     - **MatchInvalidTicketIdsExtensionKey** = **"invalid_ticket_ids"**. Value type stored in the match's **Extensions** map: a **google.protobuf.Any** wrapping a **google.protobuf.ListValue** (Go type **structpb.ListValue**) whose elements are all string values. Lists every roster ticket ID in the match that failed ticket ID validation; om-core does not (and cannot) deactivate these tickets. Set only when at least one roster ticket ID is invalid. Set in BOTH deactivation modes (**OM_MATCH_TICKET_DEACTIVATION_WAIT** true or false).
     - **MatchDeactivationFailedTicketIdsExtensionKey** = **"deactivation_failed_ticket_ids"**. Same value type (Any wrapping a ListValue of strings). Lists every valid roster ticket ID whose deactivation write to the state store failed, so the ticket may still be active and could be matched again. Set ONLY when **OM_MATCH_TICKET_DEACTIVATION_WAIT** is **true** (in that mode om-core finishes deactivating before returning the match, so it knows which writes failed); never set when that variable is **false**, because the match is returned before deactivation is attempted. Set only when at least one write failed.
     - The doc comment on each constant must state the value type, which tickets are listed, the "only set when at least one" rule, and (for the deactivation-failed key) the WAIT=true-only rule and the fact that if every write failed, the **deactivation_timeout** extension is also set. These comments are the primary public documentation of the contract for Go importers and reviewers.
  3. **ErrorInfo Identification Constants** (unexported; implementer chooses names): a reason string **"MMF_FAILURE"** and a domain string **"open-match"**, documented as identifying the **errdetails.ErrorInfo** entries (one per failed MMF) attached to the status **InvokeMatchmakingFunctions** returns when any invoked MMF fails. Tests in the same package compare against these constants.
  4. **Ticket ID List Annotation Helpers** (unexported):
     - A generic helper that takes a pointer to **pb.Match**, an extension key string, and a slice of string IDs. It does nothing if the match is nil or the slice is empty. Otherwise it converts the IDs to a slice of interface values (preserving order and duplicates), builds a list with **structpb.NewList**, wraps it with **anypb.New**, lazily allocates the match's **Extensions** map if nil, and stores the Any under the key (overwriting any value an MMF may have placed under the same reserved key). If list construction fails, log at Error level "Failed to build <key> extension: <err>" and return; if Any marshalling fails, log at Error level "Failed to marshal <key> extension: <err>" and return.
     - A thin wrapper for the invalid-ticket key and a thin wrapper for the deactivation-failed key, each calling the generic helper. Their doc comments must state that they mutate the match and therefore must only be called before the match is handed off for sending (the match is sent by another goroutine; mutating afterwards would be a data race). The deactivation-failed wrapper's comment must state it is only used when **OM_MATCH_TICKET_DEACTIVATION_WAIT** is true.
  5. **MMF Failure Record and Final Status Builder** (unexported):
     - A small record type holding the failed MMF's name (from **GetName** on the **pb.MatchmakingFunctionSpec**) and the error the MMF fan-out goroutine returned.
     - A status-unwrapping helper: given an error, use **errors.As** to find any error in the wrap chain implementing a method **GRPCStatus** returning a pointer to **status.Status**, and return that status; if none is found, return a new status with **codes.Unknown** and the error's **Error** string as its message. (Most fan-out goroutine errors are gRPC status errors wrapped with the standard library's error-wrapping verb, and some are returned unwrapped, so inspecting only the outermost error is insufficient; the helper must unwrap. Because every existing path builds its status with **codes.Internal** (mid-stream errors are re-wrapped as **codes.Internal** with a message beginning "MMF Failure: " that embeds the original status text), the **grpc_code** metadata is currently always "Internal".)
     - A status builder taking the total number of requested MMFs (the length of **GetMmfs** on the request) and the slice of failure records, returning an **error**:
       - For each failure, in slice order: unwrap its status; append a summary part consisting of the MMF name, a colon and a space, then the status's message; and append an **errdetails.ErrorInfo** with **Reason** "MMF_FAILURE", **Domain** "open-match", and **Metadata** containing exactly three keys: **"mmf_name"** (the MMF name), **"grpc_code"** (the unwrapped status code's string name, as produced by the code's **String** method, for example "Internal"), and **"message"** (the unwrapped status message).
       - Create a status with gRPC code **codes.Internal** whose message is: the number of failures, the word "of", the total number of requested MMFs, the phrase "matchmaking functions failed:", a space, then all summary parts joined with a semicolon followed by a space. Example shape (prose): "2 of 3 matchmaking functions failed: rest-nyi-mmf: <message>; bad-uri-mmf: <message>". The substring "<failed> of <total> matchmaking functions failed" and the substring "<mmf name>: <ErrorInfo message metadata>" are relied on by tests.
       - Attach all ErrorInfo details via the status's **WithDetails** method; on success use the detailed status; on failure log at Error level "Failed to attach MMF failure details to status: <err>" and fall back to the status without details.
       - Return the status's **Err**.
       - Its doc comment must state that every match the MMFs returned has already been streamed to the caller by the time this status is returned, so the caller receives all matches followed by this error, and that one ErrorInfo per failed MMF carries the name, gRPC code and message for programmatic use.
  6. **Updated InvokeMatchmakingFunctions Doc Comment**: Change "it deactivates all tickets contained in the match" to "it deactivates all valid tickets contained in the match", and add a paragraph stating that from the caller's point of view the handler behaves like an RPC framework: every response an MMF streams back is forwarded to the caller (including matches with no valid tickets and responses with no match at all), and if any MMF fails, the stream ends with an error status describing every failure after all returned matches have been sent.
  7. **MMF Failure Aggregation in the Fan-Out Loop**:
     - Before the per-MMF loop, declare a **sync.Mutex** and a slice of failure records (with a comment explaining these errors are returned to the caller after all matches have been streamed so that, like an RPC framework, om-core never hides an MMF failure).
     - Change the MMF fan-out goroutine to use a named **error** return value. Keep the existing first deferred call that marks the MMF wait group done; then register a second deferred closure (which, by LIFO ordering, runs BEFORE the wait group's Done) that, if the named error is non-nil, locks the mutex, appends a failure record with the MMF's name and the error, and unlocks. A comment must state this ordering guarantees every failure is recorded before the MMF wait group's Wait returns.
     - All existing early-return error paths (URL parse failure, REST type not implemented, ID token fetch failure, dial failure, token refresh failure, connect/send failure, mid-stream receive failure, mid-stream auth retry failures) keep their current error values, log lines, and **om_core.mmf.failures** increments; their returned errors are now captured by the deferred recorder.
     - At the end of the goroutine, after the receive loop exits on **io.EOF**, return **nil** instead of the loop's error variable (which holds **io.EOF**). This is mandatory: returning **io.EOF** would now record every successful MMF as a failure. Comment: the stream ended with **io.EOF**, which is success. Update the trailing lint-suppression comment on the goroutine invocation to say errors are recorded in the failure slice.
     - After the existing sequence (MMF wait group Wait, close the match channel, fan-in wait group Wait), add: if the failure slice is non-empty, return the result of the status builder (total = length of **GetMmfs** on the request); otherwise return nil. Comment: every match has been streamed; now report any MMF failures. Reading the slice without the mutex here is safe because the MMF wait group's Wait establishes happens-before with every append. - **Justification**: At the baseline, chunk packing lived inline in **InvokeMatchmakingFunctions** with a local 4,000,000-byte budget and under-counted the real serialized size in two ways: (a) the empty-chunk baseline was measured as a **pb.ChunkedMmfRunRequest** containing only the request profile, ignoring the cloned valid pools and their empty participant rosters that the chunk builder actually adds; and (b) each ticket was counted as its bare serialized size, ignoring the repeated-field tag and length prefix protobuf writes for each element of the roster's tickets field. Comment: the 4 MiB soft limit every message om-core sends to an MMF must stay under; it is gRPC's default maximum received message size; some middleware (proxies, service meshes, load balancers) enforces the same limit and silently discards larger messages; staying under it means MMFs work with default gRPC settings and through that middleware without anyone raising limits.

- **Justification**:
  1. **No HTTP method other than POST**: om-core's grpc-gateway maps **DeactivateTickets** to HTTP **DELETE**, which the POST-only request helper could not send.
  2. **Token cache hazards**: The baseline cache minted tokens while holding its single mutex, so one slow metadata-server mint blocked every request to every audience. Mints were not bounded by a timeout or the request context, so a hung metadata server hung requests forever. The cache was keyed on comparing access-token strings.
  3. **Wrong 403 handling**: The baseline refreshed the token and retried on HTTP 403. A 403 from Cloud Run means the calling service account lacks the Cloud Run Invoker role, which a new token cannot fix, so every 403 doubled the requests and token mints.
  4. **Credential leak**: At trace level the baseline logged all request headers, including the bearer token. It also checked the global logrus level, not the client's own logger.
  5. **No per-attempt bound**: The director shares one **http.Client** between unary calls and the long-lived **InvokeMatchmakingFunctions** stream, so the client cannot have an overall timeout.     - Create a logger with fields **component** set to **tester** and **operation** set to **generate_tickets**.
    - Read **TICKET_CREATION_CYCLES**.
    - Read **TICKET_ARRIVAL_SEED** as an unsigned 64-bit integer. If it is 0, replace it with a random unsigned 64-bit value. Build a PCG source with the seed as both of its arguments. It is used only from this goroutine.
    - Log the seed at Debug level ("test ticket arrival seed: " followed by the number).
    - Hold the carry-over state: one pending request plus its original arrival time.
    - Create a WaitGroup for the per-cycle reporters and wait on it in a deferred call, so the function doesn't return before the last cycle's report.
  - **Per cycle** (counting cycles from 1 to the configured number):
    1. Return if the context is done.
    2. Derive a cycle context.
    3. Snapshot TPC and the ticket function under the TPC mutex.
    4. Compute the cycle duration from **TICKET_CREATION_CYCLE_DURATION_MS** and draw the arrival schedule (TPC offsets across the duration).
    5. Start the deadline timer and record the start time.
    6. **Arrival goroutine**: It uses an unbuffered channel of arrival times and closes it when finished. It uses one reusable timer, created and stopped immediately, with a deferred stop. For each offset, the arrival time is the start plus the offset. If the time remaining is greater than the 1 ms granularity, reset the timer and wait for it or for cycle-context done (return on done). Then send the arrival time on the channel, selecting against cycle-context done. Because the channel is unbuffered, later arrivals wait while the main loop is blocked handing a request to the queue, and they are then released back-to-back.
    7. **Per-cycle state**:
       - A queued count, accessed only from the main goroutine.
       - A flag saying whether the duration has been recorded, plus the measured duration.
       - A confirmation WaitGroup and two atomic counters (**sync/atomic** **Int64**) for confirmed and failed results.
       - **Record duration**, done once per cycle: the time since the start goes to **mmqueue.ticket.generation.cycle_duration** in ms.
       - **Finish cycle**: record the duration if it hasn't been recorded, record the queued count on **mmqueue.tpc.actual** at the deadline, and write the Info log line (below).
    8. **Main select loop**:
       - **Context done**: stop the deadline timer, cancel the cycle, and return.
       - **Arrival channel closed**: set the channel to nil, record the duration (all arrivals queued), and keep waiting for the deadline.
       - **Arrival received**: If a carry-over request exists, take it, clear the carry-over, and use its original arrival time in place of the received one. Otherwise build a new request: the ticket from the ticket function, or an empty **pb.Ticket** if there is no function, and a new ResultChan of capacity 1 (the comment says the buffer is there so the queue never blocks reporting a result, even if nobody is listening any more). The generated request's Ctx is left nil. Then select:
         - **Context done**: stop, cancel, and return.
         - **Deadline**: save the request and its arrival time as the carry-over, finish the cycle, and break out of the loop.
         - **Sent on ClientRequestChan**: increment the queued count, record **mmqueue.ticket.arrival_lag** as the time since the arrival in fractional ms (microseconds divided by 1000.0), then start a confirmation watcher, tracked by the confirmation WaitGroup. The watcher waits on the **parent** context (not the cycle context, so that late results still count). It counts confirmed when it receives a value of 200 on an open channel. It counts failed for any other value, or when the channel was closed without a value. If the parent context is done, it counts neither.
       - **Deadline**: finish the cycle and break.
    9. After the loop: stop the deadline timer and cancel the cycle context, which stops the arrival goroutine.
    10. **Per-cycle reporter goroutine**: It is tracked by the reporter WaitGroup and receives the cycle number and queued count. It waits for all confirmation watchers of that cycle. If the parent context is done, it returns without recording (the outstanding results were abandoned). Otherwise it records the confirmed count on **mmqueue.tpc.confirmed** and writes the second Info line. It doesn't block the next cycle.
  - **Carry-over semantics**: A carried request consumes the first arrival slot of the next cycle. If the next cycle has no arrivals (TPC 0), it stays pending. Any carry-over left after the final cycle is dropped; it was never handed to the queue.
  - **Log lines (Info, logger fields as above)**:

  1. **Re-activating assigned players (G1)**: the baseline rejection helper queued a rejected match's tickets for re-activation immediately.   2. **Signals during startup were ignored**: signal capture was set up with a plain channel, but nothing read it until after startup completed, so a SIGTERM delivered while the process waited on the om-core connection check did nothing. A second signal during a slow shutdown also could not force-exit.
  3. **Unbounded and incomplete connection check**: the baseline validated the om-core connection twice (once per client) with an unbounded context, treated only errors containing the substring "connect: connection refused" as fatal, and continued running on every other error (wrong URL, DNS failure, timeout, 401/403 from Cloud Run), producing a matchmaker that silently did nothing.
  4. **Default ServeMux leakage**: all handlers (application endpoints, the blank-imported pprof handlers, and the metrics package's **/metrics** handler) were registered on the process-global default ServeMux, so every endpoint was served on every port (the application port served **/metrics** and the Prometheus port served **/tickets**). The HTTP server also had no header-read timeout (Slowloris exposure).
  5. **State-changing GET**: **/tickets** accepted any HTTP method, so crawlers, health checkers or a browser could create tickets.
  6. **Orphaned tickets and wrong status codes**: the ticket request was not tied to the HTTP request's context, so a disconnected client's ticket was still created and matched; a disconnected client was "answered" with 408 nobody could read; an abandoned (closed) result channel would be read as status 0 and passed to the response writer; and a request waiting for the queue during shutdown blocked until the queue answered.
  7. **Unbounded shutdown**: shutdown waited for all background work with no bound, then stopped Pub/Sub, then gave the HTTP server 10s, so total shutdown could exceed Cloud Run's roughly 10 second SIGTERM-to-SIGKILL window and lose the final metrics.
  8. **Director-driven exit ignored**: when the director stopped on its own (**NUM_MM_CYCLES** or **NUM_CONSECUTIVE_EMPTY_MM_CYCLES_BEFORE_QUIT** reached), the process kept running forever.
  9. **Untracked goroutines**: ticket generation and the in-process MMF servers were started without wait group tracking and their start errors were discarded.
  10. **Port collision**: the default **PORT** was 8080, the same as om-core's local default, so the documented local workflow (om-core plus matchmaker on one machine) failed to bind.
  11. **Skill-tier segmentation (user work in progress, included in this commit)**: the baseline harness had one zone and one game mode whose pool copied the director's **EveryTicket** creation-time window, which is computed once at package init and eventually stops matching new tickets on a long-running instance. The new configuration builds 44 profiles (11 zones by 4 MMR tiers) with deliberately overlapping MMR tier boundaries, to exercise same-cycle collision handling at realistic profile counts, and makes the DEBUG MMF opt-in because it doubles MMF invocations and never produces matches.
