# Open Match 2 Architecture, Protobuf Schema & API Reference

## 1. Dual Server Architecture (`server.go` & `main.go`)

`om-core` starts two listeners inside the same process (`server.go`):
1. **Unexposed gRPC Server** on `OM_GRPC_PORT` (default `50581`): Registers `pb.OpenMatchServiceServer` with panic-recovery interceptors (`unaryPanicRecoveryInterceptor`, `streamPanicRecoveryInterceptor`) and OpenTelemetry RPC stats handler (`Handler`).
2. **Exposed HTTP `grpc-gateway` Proxy** on `PORT` (default `8080`): Reverse-proxies RESTful HTTP/JSON requests to `localhost:50581`. Cloud Run and GKE services expose port `8080`.

## 2. `OpenMatchService` RPC & HTTP/REST Endpoints (`proto/api.proto`, `proto/api.yaml`)

| gRPC Method | HTTP Method & Path | Request Message | Response Message | Production Status & Behavior |
| :--- | :--- | :--- | :--- | :--- |
| `CreateTicket` | `POST /tickets` | `CreateTicketRequest` | `CreateTicketResponse` | **Active.** Persists ticket in `inactive` state; returns server-assigned `ticket_id` (`<ms>-<seq>`). |
| `ActivateTickets` | `POST /tickets:activate` | `ActivateTicketsRequest` | `ActivateTicketsResponse` | **Active.** Moves up to `OM_MAX_STATE_UPDATES_PER_CALL` (500) ticket IDs into `active` state so they appear in pools. |
| `DeactivateTickets` | `DELETE /tickets:deactivate` | `DeactivateTicketsRequest` | `DeactivateTicketsResponse` | **Active.** Moves up to `OM_MAX_STATE_UPDATES_PER_CALL` (500) ticket IDs into `inactive` state (e.g., player cancelled queue). |
| `InvokeMatchmakingFunctions` | `POST /matches:fetch` | `MmfRequest` | `stream StreamedMmfResponse` | **Active.** Snapshots active tickets, evaluates pool filters, invokes all specified MMFs concurrently, auto-deactivates matched roster tickets, and streams back `Match` objects. |
| `CreateAssignments` | `POST /assignments:create` | `CreateAssignmentsRequest` | `CreateAssignmentsResponse` | **DEPRECATED (Dev/Test only).** Legacy OM1 compatibility. Do not use in production. |
| `WatchAssignments` | `POST /assignments:watch` | `WatchAssignmentsRequest` | `stream StreamedWatchAssignmentsResponse` | **DEPRECATED (Dev/Test only).** Legacy OM1 compatibility. Push assignments from Director directly to clients instead. |

> **HTTP Streaming Gotcha**: When calling `POST /matches:fetch` (`InvokeMatchmakingFunctions`) via HTTP/JSON (`grpc-gateway`), each newline-delimited JSON response chunk is wrapped inside a `"result"` key: `{"result": {"match": { ... }}}`. Clients must unwrap `"result"` before unmarshalling into `pb.StreamedMmfResponse`.

## 3. Core Protobuf Messages (`proto/messages.proto` & `proto/mmf.proto`)

### `Ticket`
- `id` (`string`): Output-only, generated by the state replicator (`^\d{13}-\d+$`). Custom IDs cannot be set here; store custom player/session IDs in `attributes.string_args` (if filterable) or `extensions` (if not filterable).
- `expiration_time` (`google.protobuf.Timestamp`): Output-only (`creation_time + OM_CACHE_TICKET_TTL_MS`).
- `attributes` (`Ticket.FilterableData`):
  - `tags` (`repeated string`): Matched by `Pool.TagPresentFilter`.
  - `string_args` (`map<string, string>`): Matched by `Pool.StringEqualsFilter`.
  - `double_args` (`map<string, double>`): Matched by `Pool.DoubleRangeFilter`.
  - `creation_time` (`google.protobuf.Timestamp`): Defaults to current server time if omitted. Matched by `Pool.CreationTimeRangeFilter`.
- `extensions` (`map<string, google.protobuf.Any>`): Ignored by `om-core` indexing; forwarded untouched to MMFs. Always prefer `extensions` over `attributes` for data not used in pool filters.

### `Pool` (`internal/filter/filter.go`)
- A `Pool` is a logical **AND (intersection)** of all filters defined on it (`tag_present_filters`, `string_equals_filters`, `double_range_filters`, `creation_time_range_filter`).
- `FilterBounds` (`DoubleRangeFilter` & `CreationTimeRangeFilter`):
  - `EXCLUDE_NONE` / `INCLUDE_BOTH` (`0`): `min <= x <= max`
  - `EXCLUDE_MIN` / `EXCLUDE_START` / `INCLUDE_MAX_ONLY` (`1`): `min < x <= max`
  - `EXCLUDE_MAX` / `EXCLUDE_END` / `INCLUDE_MIN_ONLY` (`2`): `min <= x < max`
  - `EXCLUDE_BOTH` / `INCLUDE_NONE` (`3`): `min < x < max`
- `participants` (`Roster`): Output-only; populated by `om-core` with all active tickets matching the pool's filters before calling MMFs.

### `Profile` & Cardinality Convention
- `name` (`string`): **Always use reverse-DNS notation with a unique suffix after the last dot**, e.g., `com.mygame.mode.us-east1.2026-10-09T02:00:00Z`. `om-core` strips everything after the final `.` when recording OpenTelemetry metric attributes (`com.mygame.mode.us-east1`) to prevent metric cardinality explosion.
- `pools` (`map<string, Pool>`): Named pools to filter and send to MMFs.

### `MatchmakingFunctionService` (`proto/mmf.proto`)
- Service implemented by your custom Matchmaking Function (MMF):
  ```protobuf
  service MatchMakingFunctionService {
    rpc Run(stream ChunkedMmfRunRequest) returns (stream StreamedMmfResponse) {}
  }
  ```
- **Request Chunking**: Because populated pools can exceed the 4 MB gRPC message limit, `om-core` splits the `Profile` across multiple `ChunkedMmfRunRequest` messages (`num_chunks` indicates the total chunks). The MMF must read all `num_chunks` messages and concatenate `pool.participants.tickets` by pool key before running matchmaking logic.
- **MMF Authentication (`internal/mmfauth/idtokencache.go`)**: When `MatchmakingFunctionSpec.host` uses `https://` or port `443` (e.g., Cloud Run MMFs), `om-core` automatically mints and caches Google OIDC ID tokens per audience (`https://<host>`) and refreshes the token once on `Unauthenticated` or `PermissionDenied` gRPC responses.
- **Recompiling Protos**: `pkg/pb` and `pkg/api` are committed to the repo. Only recompile `proto/*.proto` if modifying the core API (see `proto/Dockerfile` and `proto/README.md`). To build an MMF in another language, compile only `proto/mmf.proto` and `proto/messages.proto`.

## 4. State Replication & `ReplicatedTicketCache` (`internal/statestore/`)

1. **Write Path (`OutgoingReplicationQueue`)**:
   - RPC handlers (`CreateTicket`, `ActivateTickets`, `DeactivateTickets`, and match roster deactivation in `InvokeMatchmakingFunctions`) enqueue `cache.UpdateRequest` items onto `tc.UpRequests`.
   - `OutgoingReplicationQueue` batches up to `OM_CACHE_OUT_MAX_QUEUE_THRESHOLD` (50) updates or waits up to `OM_CACHE_OUT_WAIT_TIMEOUT_MS` (500 ms) before calling `Replicator.SendUpdates()`.
   - When `OM_CACHE_PACK_TICKET_STATE_UPDATES=true`, multi-ticket activations/deactivations and contiguous same-command (`Activate` or `Deactivate`) requests are packed into a single Redis Stream entry (up to `OM_MAX_STATE_UPDATES_PER_CALL` keys).
   - Each Redis pipeline batch appends `XTRIM om-replication MINID ~ <now - OM_CACHE_TICKET_TTL_MS>` for O(1) macro-node stream eviction.
2. **Read & Apply Path (`IncomingReplicationQueue`)**:
   - Every `om-core` instance continuously polls Redis (`XREAD BLOCK <OM_CACHE_IN_WAIT_TIMEOUT_MS> COUNT <OM_CACHE_IN_MAX_UPDATES_PER_POLL> STREAMS om-replication <last_repl_id>`) from `OM_REDIS_READ_HOST`.
   - A separate applier goroutine drains buffered updates in bounded cycles (`OM_CACHE_IN_MAX_APPLY_DURATION_MS`), updating `Tickets`, `InactiveSet`, `ActiveTickets`, and advancing the watermark `appliedReplId` (`recordApplied`).
   - `InvokeMatchmakingFunctions` calls `tc.SnapshotActiveTickets()` for a lock-free point-in-time snapshot of `ActiveTickets`.
3. **Local Expiration (`expireCacheEntries`)**:
   - Every `OM_CACHE_EXPIRATION_INTERVAL_MS` (1000 ms), `ReplicatedTicketCache` pops expired entries from deadline-ordered min-heaps (`ticketHeap`, `inactiveHeap`, `assignmentHeap`), deleting at most `OM_CACHE_EXPIRATION_MAX_DELETES_PER_CYCLE` (5000) entries per cycle in small lock chunks so mass expirations never stall replication apply cycles.

## 5. Open Match 1 vs. Open Match 2 Quick Comparison (`docs/MIGRATION.md`)

| Area | Open Match 1 (OM1) | Open Match 2 (OM2) |
| :--- | :--- | :--- |
| **Deployment Topology** | Multiple microservices (`frontend`, `backend`, `query`, `synchronizer`, `evaluator`) | Single stateless binary/container (`om-core`) |
| **Client Protocol** | Pure gRPC | gRPC or HTTP/JSON via built-in `grpc-gateway` (`PORT:8080`) |
| **Ticket State** | Active immediately on creation; manual `DeleteTicket` required | Starts **`inactive`** (`ActivateTickets` required); auto-expires via TTL (`OM_CACHE_TICKET_TTL_MS`); no `DeleteTicket` |
| **Ticket Fields** | `search_fields` (`SearchFields`), custom `id` allowed | `attributes` (`FilterableData`), `id` is server-assigned Redis Stream ID |
| **MMF Input** | MMF calls Query Service (`QueryPools`) to fetch tickets | `om-core` filters local cache and streams `ChunkedMmfRunRequest` to MMF |
| **Collision Resolution** | Built-in `synchronizer` + `evaluator` window | Removed; MMFs return final `Match` objects; **Director** de-collides and re-activates discarded tickets |
| **Assignments** | Director calls `AssignTickets`; clients poll `GetAssignments` | Deprecated; Director sends assignments directly to game client notification service |
